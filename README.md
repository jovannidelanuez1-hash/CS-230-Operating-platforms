CS 230 Module Eight Journal: The Gaming Room Reflection

1. Client and Software Requirements

The client for this project was The Gaming Room, a company that wanted to expand its existing Android game, Draw It or Lose It, to additional operating platforms. The client needed a software design that could support multiple users, maintain consistent game information, and provide a reliable experience across different devices and operating systems. The design also needed to consider software architecture, memory management, storage requirements, security, scalability, and the use of a distributed environment. The goal was to recommend an approach that would allow the application to grow while remaining maintainable and accessible to users.

2. What I Did Particularly Well

One area I did particularly well was organizing the software design document and explaining the advantages and disadvantages of different architectural approaches. I evaluated operating systems, server-side hosting options, and the benefits of using a shared web-based interface instead of developing separate native applications for every platform. I also considered performance limitations, network availability, and the importance of managing system resources efficiently. These considerations helped me create a design that addressed the client's business needs while providing useful information for the development team.

3. What I Found Helpful About the Design Process

Working through the design document helped me understand the importance of planning before writing code. Defining the requirements and considering the system architecture made it easier to identify the components the application would need and how they would work together. The design process also helped me think about potential problems involving scalability, compatibility, memory usage, and communication between clients and servers. By considering these issues early, developers can reduce errors, avoid unnecessary changes, and make better technical decisions during implementation.

4. What I Would Revise

If I could revise one part of my software design document, I would expand the explanation of scalability and server-side resource management. I would provide more specific examples of how load balancing, horizontal scaling, and monitoring could help the application support an increasing number of players. I would also explain how server resources could be adjusted as demand changes and how the system could maintain reliability during periods of heavy use. These improvements would make my recommendations more detailed and provide the development team with a clearer understanding of how the proposed architecture could support future growth.

5. Interpreting and Implementing User Needs

I interpreted the client's needs by focusing on cross-platform compatibility, a consistent user experience, reliable communication, and the ability to support multiple players. I considered how a shared web-based interface could reduce development and maintenance costs while allowing users to access the game from different operating systems. I also considered performance, security, and network availability because these factors can affect the overall gaming experience. Understanding user needs is important because software must solve the problems it was designed to address. A technically functional application may still fail if it is difficult to use, unreliable, or incompatible with the devices its intended users depend on.

6. My Approach to Software Design

My approach to software design involved reviewing the requirements, identifying the client's priorities, comparing possible solutions, and evaluating the advantages and disadvantages of each approach. I considered the system's architecture, operating system compatibility, hosting environment, resource management, and opportunities for future expansion. In future projects, I would continue using requirements analysis, architectural comparisons, diagrams, and clear documentation to organize my decisions before implementation. I would also consider scalability, security, testing, and maintainability from the beginning. These strategies would help me create software designs that meet user expectations, support development teams, and adapt to changing business requirements.
